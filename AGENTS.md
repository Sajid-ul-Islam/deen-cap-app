## 1. Repository Purpose & Architecture Summary

This repository contains the source code, native configurations, and tooling for **DEEN Commerce** (`com.deencommerce.app`), an Android hybrid application powered by **Capacitor 6+**.

The primary objective of this project is to deliver the live e-commerce platform [https://deencommerce.com/](https://deencommerce.com/) inside a secure, hardware-accelerated Android WebView, while progressively integrating native device capabilities (such as hardware back-button intercept, push notifications, offline detection, and native payment gateways).

```
+--------------------------------------------------------------+
|                     DEEN Commerce Android                    |
|                                                              |
|   [Native Shell: android/]                                   |
|   └── MainActivity (Capacitor Bridge & Lifecycle)            |
|       └── Hardware Acceleration & Android Manifest           |
|                                                              |
|   [Capacitor Bridge Runtime]                                 |
|   └── capacitor.config.ts -> Plugin Registry                 |
|                                                              |
|   [WebView Engine]                                           |
|   ├── Remote Storefront: https://deencommerce.com/           |
|   └── Fallback Shell: www/index.html (Offline Resilience)    |
+--------------------------------------------------------------+
```

## 4. Non-Negotiable Operational Rules ("Do NOT")

Agents operating in this repository **MUST NOT**:

1. 🚫 **NEVER hand-edit `android/app/src/main/assets/public/`:** This directory is automatically purged and regenerated by `npx cap sync`. Any manual modifications here will be erased.
2. 🚫 **NEVER edit native Android files (`android/`) without explicit instruction:** Avoid modifying Java/Kotlin source, Gradle build scripts, or `AndroidManifest.xml` unless the user's prompt specifically requests native-layer customization.
3. 🚫 **NEVER commit sensitive credentials or build artifacts:**
   - Keystores (`*.keystore`, `*.jks`)
   - `key.properties`
   - `google-services.json`
   - Environment files (`.env`, `.env.local`, `.env.production`)
   - Gradle build directories (`android/.gradle/`, `android/app/build/`)
   - Node dependencies (`node_modules/`)
4. 🚫 **NEVER modify the core remote URL without environmental gating:** The production target is strictly `https://deencommerce.com/`. Do not hardcode localhost or staging URLs in production commits.
5. 🚫 **NEVER introduce `any` types in TypeScript:** All bridge interfaces and wrappers must be strongly typed.
6. 🚫 **NEVER downgrade Capacitor dependencies:** Any changes to `@capacitor/core`, `@capacitor/cli`, or native plugins must preserve version parity at `6.x`.

## 5. Mandatory Operational Directives ("Always")

Agents operating in this repository **MUST ALWAYS**:

1. ✅ **Run `npx cap sync android` after modifying bridge configurations:** Whenever `capacitor.config.ts`, `package.json`, or any `@capacitor/*` plugin is added or modified, immediately execute `npx cap sync android`.
2. ✅ **Maintain offline resilience:** When touching the web shell in `www/`, ensure that network dropouts produce a graceful fallback screen rather than a browser standard error code (`net::ERR_INTERNET_DISCONNECTED`).
3. ✅ **Preserve Android back button handling:** Maintain event listeners for the Android hardware/gesture back button (`@capacitor/app` `backButton` event) so users can navigate backwards through WebView history without accidentally quitting the application.
4. ✅ **Ensure code style compliance:** Format all TypeScript and Markdown files according to the project's Prettier and ESLint standards.
5. ✅ **Keep documentation synchronized:** When adding a new plugin, environment variable, or build script, update `README.md`, `ARCHITECTURE.md`, `ENV.md`, or `CHANGELOG.md` as appropriate.

## 6. Common Agent Workflows & Commands

### 6.1 Adding a Capacitor Plugin

When asked to integrate a new native capability (e.g., Network, Device, App, or Splash Screen):

```bash
# 1. Install the official plugin package
npm install @capacitor/network

# 2. Sync native Android project bindings
npx cap sync android

# 3. Verify Android build compiles cleanly
cd android && ./gradlew assembleDebug
```

### 6.2 Testing & Local Validation

```bash
# Typecheck TypeScript files
npx tsc --noEmit

# Run ESLint validation
npm run lint

# Synchronize web assets to native container
npx cap copy android
```

### 6.3 Building Android Debug Artifacts

```bash
# Clean previous builds and assemble debug APK
cd android
./gradlew clean
./gradlew assembleDebug

# Output APK path:
# android/app/build/outputs/apk/debug/app-debug.apk
```

### 6.4 Launching on Device or Emulator

```bash
# Run directly on active ADB target
npx cap run android

# Alternatively, open Android Studio to view Logcat and layout inspector
npx cap open android
```

### 6.5 Debugging Remote WebView

To inspect the live WebView running inside the Android container:
1. Connect target device or launch emulator.
2. Open Google Chrome on host machine.
3. Navigate to `chrome://inspect/#devices`.
4. Locate the `com.deencommerce.app` WebView target and select **Inspect**.

## 7. Code Quality & Formatting Conventions

- **TypeScript Standard:** Target ES2022, module resolution Node16/Bundler, with `strict: true`, `noImplicitAny: true`, and `strictNullChecks: true`.
- **Prettier Configuration:**
  ```json
  {
    "semi": true,
    "singleQuote": true,
    "tabWidth": 2,
    "trailingComma": "all",
    "printWidth": 100
  }
  ```
- **Error Handling:** All asynchronous calls across the Capacitor bridge must be wrapped in `try/catch` blocks with explicit fallback mechanisms if a native method is unavailable (e.g., when running in a standard web browser).

## 8. Testing & Validation Expectations

Before submitting a PR or concluding an agent session:

1. **Configuration Integrity:** Verify `capacitor.config.ts` parses correctly and contains the verified `appId: 'com.deencommerce.app'`.
2. **Build Verification:** Run `cd android && ./gradlew assembleDebug` to confirm that the Java/Kotlin sources, Gradle dependencies, and AAPT resources compile without errors.
3. **No Dangling References:** Ensure no dangling `console.log` statements or unhandled promise rejections exist in frontend bridge scripts.

## 9. Escalation Protocols & Human-in-the-Loop Triggers

Agents must immediately pause and request human guidance under the following conditions:

| Scenario | Trigger / Symptom | Action Required |
| :--- | :--- | :--- |
| **Play Store Secrets** | Requesting release keystore passwords, alias keys, or API tokens | Stop. Prompt human developer to provide secrets via environment or local `key.properties`. |
| **Google Services Config** | Setting up FCM Push Notifications | Stop. Prompt human developer to generate and supply `google-services.json` from Firebase Console. |
| **Domain SSL/TLS Errors** | WebView fails to load `https://deencommerce.com/` with SSL handshake error | Stop. Prompt human developer to inspect remote server TLS certificate and HSTS configuration. |
| **Major Gradle Mismatch** | Gradle build breaks due to incompatibilities between local JDK and AGP | Escalate to human with exact error logs and recommended JDK/AGP versions. |
